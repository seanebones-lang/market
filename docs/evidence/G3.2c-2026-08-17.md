## Outcome

The repository can now convert a local, strict-schema Robinhood Crypto Trading API v2 fixture into
a sanitized, immutable, independently rederived execution-cost observation. The observation keeps
displayed spread, quantity-aware price impact, fee ratio, estimated fee, estimated total
cost/credit, and midpoint-relative all-in costs separate.

This passes the engineering checkpoint needed to specify a future cost-sampling protocol. It does
not answer the empirical question. No source in this increment came from Robinhood, and none of its
synthetic numbers may be used as a current cost estimate or strategy input.

## Read boundary

The source contract names four official v2 GET paths only:

1. accounts;
2. trading pairs;
3. best bid/ask; and
4. quantity-aware estimated price.

The implementation contains no HTTP library import, base URL, authentication header builder,
signature function, private-key reader, request executor, retry loop, order endpoint, order-history
endpoint, POST method, or cancellation path. Endpoint identities are a descriptive `StrEnum`, not
an executable client.

The preexisting broker order lock remains unchanged and is still tested across every combination
of runtime flags.

## Admission and failure checks

The new tests prove:

- only the four named cost resources are present and all report `GET`;
- no allowlisted path contains `/orders/` or cancel;
- unknown fixture fields fail strict Pydantic validation;
- account status, API tradability, pair identity, increment, minimum, and maximum are checked;
- best and estimated books must be ordered;
- bid and ask estimates must exactly match requested symbol and quantity;
- account, bid, and ask fee ratios must agree;
- four local receive timestamps must fit inside one 60-second capture cycle;
- broker estimate timestamps older than 60 seconds or more than 5 seconds in the future fail;
- estimated buy cost and sell credit arithmetic must reconcile within $0.02;
- account number and buying power are redacted before persistence;
- authentication and private-key key spellings are recursively redacted;
- a second write to the same content-addressed directory is refused;
- a modified observation fails byte-count or SHA-256 verification; and
- a verified bundle rederives byte-equivalent typed observation content from its sanitized source.
