## Implemented contract

The system accepts no round-trip fee input. Its only configurable transaction-fee rate is:

```text
transaction_fee_bps_per_fill_assumption
```

For every buy or sell execution:

```text
executed notional = executed quantity * fill price
fee               = executed notional
                    * transaction_fee_bps_per_fill_assumption / 10,000
```

The rate is applied in full to each fill. It is never divided by two. A round-trip cost is a
derived sum of its entry and exit fill costs.

The contract is shared by the event-driven backtester and paper `SimBroker`. Simulated fills record
`fee_calculation_basis=executed_notional_per_fill` and the named per-fill assumption.

## Removed ambiguity

The following Python/artifact/CLI names were removed rather than retained as aliases:

```text
fee_bps
transaction_fee_bps_assumption
transaction_fee_bps_applied
--fee-bps
--transaction-fee-bps-assumption
```

The CLI exposes only `--transaction-fee-bps-per-fill-assumption`. Both removed flags return exit
code 2 as unrecognized arguments. The legacy unclassified profile preserves its 5-bps default, but
schema-v5 artifacts identify it as a per-fill assumption.

## Golden per-fill calculation

Assumption: 95 bps, one `$100` buy fill, and one `$100` sell fill.

| Fill | Executed notional | Applied rate | Fee |
|---|---:|---:|---:|
| Buy | `$100` | `95 bps` | `$0.95` |
| Sell | `$100` | `95 bps` | `$0.95` |
| Derived two-fill lifecycle | `$200` | Not a separate input | `$1.90` |

This proves 95 bps is not interpreted as a round-trip total and is not split into 47.5 bps per
side.

No ambiguous fee key appears in the generated summary. The paper simulator also records the same
calculation basis and assumption in each fill's raw provenance.
