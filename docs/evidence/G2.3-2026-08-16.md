## Official-source basis

The implementation was checked against Robinhood's official material on 2026-08-16:

| Official statement | Modeling consequence |
|---|---|
| API v1 places orders without fee tiers; API v2 places orders with fee tiers | v1 and v2 are separate profiles and cannot share one generic rate |
| Market-maker routing has no separate customer commission; Robinhood's economics are included in the spread | v1 market-maker profile requires a positive spread assumption and applies zero separate fee |
| Exchange-routing fees are percentage charges on executed dollar value | v2 fee assumption is applied to each fill's executed notional |
| v2 API executions are charged the taker rate while maker/taker rollout is incomplete | current v2 profile is explicitly named `exchange_taker` |
| 2026-06-22 standard schedule lists taker tiers from 0.95% to 0.03% | the fixture's 95-bps rate is a declared lowest-volume-tier assumption, not an observed account rate |

## Implemented contracts

| Profile | Contract |
|---|---|
| `legacy_unclassified` | Preserves prior behavior and the default 5-bps legacy fee; explicitly marked unclassified |
| `robinhood_crypto_api_v1_market_maker` | Requires bid/ask execution and positive full-spread assumption; forbids the legacy fee and any nonzero transaction-fee input |
| `robinhood_crypto_api_v2_exchange_taker` | Requires bid/ask execution, positive full-spread assumption, and positive executed-notional taker-fee assumption; forbids the legacy fee input |

Every summary, eligible-order event, fill event, rejected-execution event, and fill artifact records:

- venue cost profile;
- venue, route, and API version;
- `configured_assumption` or `legacy_unclassified` input classification;
- transaction-fee treatment;
- configured transaction-fee assumption; and
- transaction-fee rate actually applied by the simulation.

No configured value is labeled observed. Artifact schema version is 4.

The 192-bps v1 fixture converts Robinhood's one-sided 96-bps ask-to-mid example into this engine's
symmetric full-spread input. That is a synthetic conversion used to prove treatment, not an
observed quote or a recommended production rate.

## Validation coverage

- v1 and v2 route/API metadata cannot collapse into one profile.
- Robinhood profiles reject raw next-open execution and zero spread.
- Robinhood profiles reject the legacy `fee_bps` input to prevent double charging.
- v1 rejects a separate transaction fee.
- v2 rejects a missing or zero transaction-fee assumption.
- Negative, non-finite, floating-point, and price-destroying fee inputs are rejected.
- Legacy default and explicit-zero behavior remain backward-compatible and labeled unclassified.

## Remaining blockers

G2.3a through G2.10 remain open. In particular, the legacy fee input still lacks a complete
per-side/round-trip contract, terminal liquidation is invisible and uncharged, and portfolio
accounting, trade lifecycle metrics, benchmarks, statistics, and reproducible run identity are
incomplete. The applicable Robinhood account tier is not read from a broker account; all research
rates remain declared assumptions. No strategy or live-money promotion is authorized.
