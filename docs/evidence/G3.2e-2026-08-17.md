## Credential boundary proved offline

- Ed25519 signing seeds are generated with PyNaCl.
- Private seed, public key, and issued API key use separate macOS Keychain service identifiers.
- The runtime checks that the active `keyring` backend is the macOS backend.
- API keys and private keys are not accepted from environment variables, `.env`, command-line
  arguments, file paths, fixtures, or config.
- Key preparation returns and prints only the public key and SHA-256 fingerprint.
- API-key completion uses a hidden interactive prompt and prints only the credential label and
  public-key fingerprint.
- Existing labels are never overwritten by lifecycle commands.
- The stored public key is compared with the public key derived from the stored private seed.
- Credential object representations replace API and private keys with `[REDACTED]`.
- Malformed-secret errors contain only stable error categories and never echo input.
- The locally installed backend resolved to `keyring.backends.macOS.Keyring`.

No Keychain `set_password` operation was executed in this evidence run. Keychain lifecycle tests
use an in-memory fake store.

## Authentication and transport proved offline

The published Robinhood example produces its exact documented signature:

```text
q/nEtxp/P2Or3hph3KejBqnw5o9qeuQ+hYRnB56FaHbjDsNUY9KhB1asMxohDnzdVFSD7StaTqjSd9U9HvaRAw==
```

The test retains the official example's Python `str(body)` representation exactly. Production
G3.2e requests are bodyless GETs and therefore do not depend on request-body serialization.

The mock transport verifies that the signature covers the exact path and query emitted by HTTPX,
including the literal, ordered four-quantity list. The production client:

- fixes `https://trading.robinhood.com` as its origin;
- admits `BTC-USD` only;
- exposes accounts, one trading pair, best bid/ask, and estimated price only;
- accepts no arbitrary method, URL, path, body, account number, or query dictionary;
- has no public `request`, `post`, `place_order`, cancel, holding, order-history, or transfer method;
- sets `trust_env=False`, forbidding environment-derived proxies;
- forbids redirects;
- caps response bodies at 1 MB;
- preserves JSON decimal values with Decimal parsing;
- validates responses under strict G3.2c Pydantic models;
- retries only transport failure and HTTP `429`, `500`, or `503`;
- makes at most three attempts;
- caps `Retry-After` at five seconds; and
- never retries HTTP `401` or `403`.

Response-body values are excluded from transport, authorization, JSON, and schema errors. A test
places a sensitive-looking account identifier in an invalid response and proves it is absent from
the resulting exception.

## Collector and missingness behavior proved offline

One synthetic cycle makes four logical reads and receives all four frozen quantities in one
estimated-price response. Before the first evidence write, the collector rejects:

- a protocol other than `rh-v2-cost-sampling-v1`;
- a source contract other than `captured_read_only_v2`;
- account or pair pagination;
- zero or multiple active API-tradable accounts;
- missing, duplicate, or extra pair/best-price rows;
- missing, duplicate, or extra symbol/side/quantity estimated-price rows; and
- any G3.2c size, timestamp, fee, arithmetic, tradability, or redaction failure.

The success test writes four content-addressed G3.2c bundles. Each re-verifies and contains
`[REDACTED]` for account number and buying power. No authentication header or credential field is
present.

A scheduled attempt must cite exactly `AUTH-G3.2E-RH-READONLY-2026-08-17` and fall between one
scheduled slot and its inclusive 60-second lateness boundary. It atomically claims that slot before
calling the client. A simulated authorization failure writes a sanitized failure code. A second
attempt at the same slot is rejected before the client is called. This proves no same-slot retry or
selective backfill path exists.

## Official-source check

The design was checked against current official Robinhood documentation on 2026-08-17:

- authenticated requests require `x-api-key`, `x-signature`, and `x-timestamp`;
- signatures use the private key, API key, timestamp, path, method, and body;
- timestamps are valid for 30 seconds;
- v2 read-only actions are available independently of order actions;
- the v2 estimated-price endpoint accepts `side=both` and at most ten comma-separated quantities;
- best prices exclude order size and fee; and
- estimated-price rows separately expose fee ratio, estimated fee, and estimated total or credit.
