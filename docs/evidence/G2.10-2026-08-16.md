## Implemented contract

Schema version 11 makes each report directory a self-contained, immutable evidence bundle. It
records and checksum-binds:

- engine version `market-event-backtester/1.0` and artifact schema 11;
- every canonical input candle and the ordered candle-sequence SHA-256;
- complete resolved strategy, risk, execution, venue-cost, benchmark, and reporting config;
- resolved-config SHA-256, nonnegative random seed, and `randomness_used=false`;
- Git commit SHA and `clean`, `dirty`, or `unavailable` worktree status; and
- executions, accounting, lifecycle/trades, benchmarks, equity, performance observations, and
  metrics.

The current engine has no stochastic path. The seed remains mandatory provenance so future
stochastic components cannot be introduced without changing the declared contract.

## Nondeterminism removed

Backtest strategy intents previously inherited `uuid4()` and wall-clock defaults from the live
domain model. G2.10 replaces those fields inside the event engine with a deterministic identifier
derived from strategy-intent sequence, bar sequence, and side, plus the signal bar's deterministic
close time. Terminal order and broker-fill identities were already deterministic.

Two runs with identical candles and resolved config now have identical events, fills, accounting,
equity, lifecycle, benchmarks, performance, and provenance. With the same run ID and injected clean
test revision, two independently written report directories are byte-identical, including their
manifests.

## Preserved data and resolved config

`input_candles.jsonl` stores every candle exactly as consumed by the strategy, including UTC time,
timeframe, source, OHLCV, receive/confirmation timestamps, closure state, and quality flags. The
input fingerprint hashes the canonical ordered candle payload rather than a mutable source path.

The resolved config captures effective values rather than only CLI arguments:

```text
starting capital
strategy name/timeframe/fast EMA/slow EMA/order quantity
risk limits and entry policy
execution model/spread/slippage/terminal model
venue/API/routing/cost classification/fee treatment/applied fee
benchmark DCA interval
equity sampling interval
random seed and randomness-use declaration
```

Changing one candle changes the input checksum without changing the config checksum. Changing only
the seed changes the config checksum without changing the input checksum.

## Code identity policy

The report resolves Git identity before creating its output directory. A `clean` status with a
40-character commit SHA is reproducible from version control. A `dirty` or `unavailable` status is
recorded but sets `code_identity_reproducible=false`; such a report can pass artifact-integrity
verification but cannot qualify as a code-identical promotable research run.

The CLI exposes no code-revision override. Tests inject a fixed clean revision only to prove exact
repeatability without depending on the test runner's working-tree state.

## Manifest contract

`manifest.json` binds 12 artifacts:

| Artifact | Role |
|---|---|
| `input_candles.jsonl` | Exact strategy input |
| `summary.json` | Resolved identity and aggregate results |
| `events.jsonl` | Ordered event timing |
| `fills.jsonl` | Executions |
| `accounting.jsonl` | Immutable portfolio journal |
| `lifecycle.jsonl` | Orders, closed trades, and round trips |
| `benchmarks.jsonl` | Comparator contract/results |
| `benchmark_fills.jsonl` | Comparator executions |
| `benchmark_equity.jsonl` | Comparator NLV curves |
| `performance.jsonl` | Metrics and alpha |
| `performance_observations.jsonl` | Full strategy statistic inputs |
| `equity.jsonl` | Strategy equity/NLV curve |

Each entry records its local path, media type, byte size, record count, and SHA-256. The verifier
rejects missing files, path escapes, size/checksum/record-count changes, summary/manifest identity
mismatches, config checksum mismatches, malformed or reordered input rows, and candle fingerprint
mismatches. A same-size byte mutation is detected.

Run directories are immutable by ID. Reusing an existing run ID raises `FileExistsError` rather
than overwriting evidence. Unsafe empty, nested, dot, or traversal run IDs fail before any directory
is created. Post-run mutation of in-memory candles/config fails report preflight.

byte-repeatability fixture uses a fixed clean revision and passes.
