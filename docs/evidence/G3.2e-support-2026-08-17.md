## Purpose

This record preserves the non-sensitive outcome of the support path frozen in
`docs/research/G3.2e-BEST-PRICE-COHERENCE-RESOLUTION.md`. It does not amend that prior plan,
reinterpret a live response, authorize another API request, or mark G3.2e complete.

Support was contacted because Robinhood's published v2 `V2BestBidAsk` component defines `bid` as
the partner-exchange price for a sell order and `ask` as the partner-exchange price for a buy
order, while the authenticated preflight observed an undocumented `timestamp` and then stopped on
two independent rows with `ask < bid`.

- presence of one undocumented `timestamp` field;

- successful authentication and read-only quote permission;
- a standard Individual Crypto account type, without its identifier;
- the sanitized local exception
  `best_bid_ask_schema_invalid:results.0:best_price_market_crossed`; and
- the fact that the collector discarded the response body and wrote no evidence.

The conversation did not disclose or upload an account number, API key, private or public signing

## Support outcomes

### Virtual-assistant response: not authoritative research evidence

Robinhood's virtual assistant stated that the published field directions remain correct, that a
crossed row can occur temporarily because aggregated sources update asynchronously, that
`ask >= bid` is the normal actionable state, that crossed rows should be rejected or retried rather
than reinterpreted, and that the undocumented `timestamp` is not a guaranteed contract field.

Those statements are useful triage context only. They were generated by a virtual assistant and
are not admitted as authoritative resolution of the API contract.

### Human frontline response: support boundary and escalation

A human Robinhood Crypto support agent did not confirm the crossed-row or `timestamp` semantics.
The agent stated that frontline support directs customers to the public API documentation for
technical endpoint behavior and cannot provide the requested detailed clarification beyond that
documentation.

After receiving the sanitized exception and the explanation that no Robinhood error or raw
response screenshot existed, the agent submitted the concern to Robinhood's back-end team for
possible specialized-team review. Robinhood assigned case `021436592` and stated that updates will
be delivered by email, normally within 24–48 business hours or longer because of request volume.
The agent did not guarantee an engineering answer or resolution time.
