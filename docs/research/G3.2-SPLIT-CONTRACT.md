## Decision

The G3 EMA study uses an expanding, anchored chronological walk-forward design followed by one
untouched final year. The machine-readable source of truth is
`config/research/g3-ema-v1-splits.json`. Every boundary is half-open UTC: `[start, end)`.

The split was chosen from calendar duration and research-power considerations, not from G3
strategy performance. No EMA pair was run to choose or validate a boundary.

## Walk-forward design

The first fold has 18 months of anchored training, three months of validation, and three months of
future testing. Each subsequent fold advances by three months:

- training always starts at `2021-08-16T00:00:00Z` and expands through the prior fold's validation;
- validation advances over the prior fold's test interval;
- test intervals are chronological, mutually disjoint, and contiguous in wall-clock time; and
- all nine test intervals end before the final holdout begins.

This is a prequential design: once an interval has served as an out-of-sample test for one fold,
it becomes historical information available to a later fold. It is never reused to revise the
earlier fold's selection or result.

## Indicator context and scoring state

The maximum registered slow EMA is 336 bars, so the bound indicator-warmup contract is 338 bars
(`slow_ema + 2`). Prior admitted bars may initialize indicators, but they are context only:

- context produces no scored return, trade, benchmark result, or parameter evidence;
- each train, validation, test, and eventual holdout scoring path starts with `$1,000` and a flat
  position;
- a context position or pre-window P&L is never carried into a scoring window;
- no context crosses a declared gap; a post-gap path must accumulate its own full warmup; and
- each scoring window ends with the G2 engine's visible, fully costed terminal liquidation.

G3.3 must encode these rules into each experiment identity so a result cannot silently change its
starting state or score warmup history.

## Holdout lock

The final holdout is sealed as:

```text
[2025-08-16T00:00:00Z, 2026-08-16T00:00:00Z)
8,750 admitted candles across 3 contiguous G1 segments
candle fingerprint 9f592ca8b481d8c34de2afca4f7ca6c5ae2ecfcd78a9aeb3a2ffbf277adb37b6
access state locked_until_g3_8
```

G3.3-G3.7 may verify the holdout boundary, count, and fingerprint but may not pass its candles to
the strategy, calculate holdout indicators, inspect holdout trades, or calculate any holdout
performance statistic. G3.8 may unlock it exactly once after the selected-pair rule, experiment
registry, multiplicity treatment, neighborhood analysis, bootstrap method, stress implementations,
and regime/benchmark analysis are frozen.

If strategy output is produced on the holdout before G3.8, the holdout is spent and protocol
version 1.0 loses confirmatory status. Moving the boundary or relabeling those candles is forbidden.

## Machine verification

Run:

```bash
./market.sh verify-research-splits --plan config/research/g3-ema-v1-splits.json
```

The verifier fails closed on:

- an unknown/extra schema field, unsafe dataset path, malformed UTC boundary, or invalid hash;
- a dataset ID, normalized SHA-256, candle fingerprint, bar count, range, or timeframe mismatch;
- a development/holdout partition that does not cover the dataset exactly;
- an expanding-training, validation, test, or holdout boundary inconsistency;
- overlapping, skipped, reordered, or holdout-leaking walk-forward tests;
- a changed per-window candle count, segment count, or ordered candle fingerprint; or
- a warmup other than `maximum_ema_period_bars + 2`.

The committed plan checksum is asserted by the hermetic test suite. Any intentional change must
create a new plan ID and protocol amendment before results; it must not overwrite this plan.
